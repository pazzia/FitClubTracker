# Постоянная подпись тестовых обновлений

Начиная с FitClub 0.3.0 build 8, Android CI использует существующий ключ из кэша fitclub-debug-signing-v1. Отпечаток сертификата этой сборки закреплён в debug-signing-sha256.txt. Это публичный отпечаток, а не закрытый ключ.

Перед тестами и сборкой tools/check_debug_signing.py проверяет сертификат хранилища ключа. После сборки он проверяет подпись APK через apksigner. При отсутствии ключа или несовпадении сертификата CI останавливается; Gradle не получает возможности автоматически создать другой debug-ключ и выпустить несовместимое обновление.

Кэш GitHub может быть удалён. Для постоянной резервной копии предусмотрен GitHub Actions secret FITCLUB_DEBUG_KEYSTORE_BASE64: base64 именно существующего debug.keystore из build 8, alias androiddebugkey, пароль android. Секрет имеет приоритет над кэшем и проходит ту же проверку. Новый ключ вместо утраченного использовать нельзя. В этой правке секрет не создавался: доступен сохранённый кэш build 8, а настройка секрета подготовлена. Закрытый ключ не хранится в репозитории и не выводится в логи.

applicationId должен оставаться com.fitclub.tracker. versionCode следующих версий должен увеличиваться. Не подменять закреплённый отпечаток для обхода проверки: это нарушит совместимость с установленным приложением.

APK из более ранних сборок, подписанные другими ключами, нельзя обновить новым ключом поверх старой установки. Для них нужен исходный закрытый ключ либо однократный перенос данных и переустановка по INSTALL_UPDATE.md. Эта правка не пересобирает build 8; commit содержит [skip ci].
